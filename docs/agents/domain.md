# Domain documentation

Read only the material relevant to the task:

- For domain terminology or behavior, use the relevant entries in root `CONTEXT.md`.
- Before changing a constant or invariant, read its section in `docs/design-rationale.md`.
- For architectural decisions, read the relevant ADRs in `docs/adr/` and the affected slice in
  `docs/palimpsest-implementation-plan.md`.

Missing optional documents need no setup ceremony. Create or update a glossary or ADR when the requested work resolves a meaningful term or lasting trade-off. Use the project's established names; explain a conflict with an ADR before changing the decision it records.
